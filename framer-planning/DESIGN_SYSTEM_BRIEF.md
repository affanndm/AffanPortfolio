# Milestone 2 Design-System Implementation Brief

## Purpose

Build a hidden Framer design-system page that turns the `SPEC.md` direction into reusable foundations before production pages are edited. The page should feel like a signal-processing board: dense, precise, cinematic, and evidence-oriented. It must not become a generic SaaS component library with rounded cards.

Do not implement this page until Milestone 1 audit deliverables are complete and Framer work is explicitly unblocked. Do not publish.

## Implementation Preconditions

- Confirm Milestone 1 deliverables are complete.
- Create a checkpoint commit before this milestone if the repository has commits available.
- Run `npx @framer/agent@latest setup` before connected Framer work.
- Connect only to the intended Framer project, then read the generated project context and task map before making changes.
- Prefer native Framer variables, text styles, component variants, breakpoints, and interactions.
- Use React Code Components only where native Framer cannot meet the interaction, performance, or reduced-motion requirement.
- Keep this design-system page hidden from navigation and hidden from search if the project is later published.

## Hidden Page Shape

Suggested page name: `00 Design System / Signal Board`

Suggested path: `/system-signal-board`

Visibility rules:

- Not linked from public navigation.
- Marked as hidden/internal in Framer page organization.
- If publishing later, set noindex where Framer allows it.

Page sections:

1. `Foundation`: color, surface, rules, spacing, grid specimens.
2. `Type System`: display, body, metadata, responsive type rows.
3. `Navigation And Actions`: nav bars, menu states, buttons, links.
4. `Ownership And Metadata`: ownership labels, project metadata, claim status patterns.
5. `Media And Evidence`: media containers, posters, captions, missing-media states.
6. `Motion Timing`: hover, reveal, ticker, menu, transition, reduced-motion demos.
7. `Accessibility States`: focus, keyboard, reduced motion, touch alternatives.

Layout should use full-width bands, thin rules, specimen rows, and column alignment. Use individual framed components only when the frame is the component being documented.

## Concept Rules

- The system metaphor is signal resolving from noise, not decoration.
- Lime is a signal indicator, not a broad paint color.
- Rules, metadata, and alignment carry structure.
- Project ownership must appear before deeper project explanation.
- Media should behave like evidence: poster, source, caption, status.
- Avoid six identical cards, big rounded SaaS panels, gradient blobs, glass effects, fake metrics, and generic icon-heading-text blocks.
- No final project claims, metrics, awards, or personal facts should be added from this page.

## Rules, Borders, Radius

Rules and borders:

- Default rule: 1px using `color/rule/default`.
- Strong rule: 1px using `color/rule/strong`.
- Active signal rule: 1px using `color/signal/lime`.
- Use rule lines to structure information instead of boxed panels.

Radius tokens:

- `radius/none`: 0px
- `radius/tiny`: 2px
- `radius/small`: 4px
- `radius/media`: 8px

Do not use large 24px+ SaaS card radii. Do not use decorative shadows as a default component treatment.

## Links

Create styles:

- `Link/Inline`: primary text with 1px underline, underline offset 0.18em.
- `Link/External`: mono label plus external-link icon.
- `Link/Metadata`: muted mono, turns primary on hover/focus.
- `Link/Project`: large title row where the rule and media respond together.

State rules:

- Hover duration: 180-260ms.
- Focus must be at least as visible as hover.
- External links need a visible affordance.
- No link meaning should rely on color alone.

## Navigation Elements

Desktop navigation:

- Fixed or sticky top layer with `AFFAN NADEEM`, section links, and contact/resume command.
- Use transparent canvas by default, raised surface only when readability requires it.
- Contrast may shift by section, but text must remain readable at all scroll positions.

Mobile navigation:

- Compact top bar with a menu button and one primary contact command.
- Menu opens into a dark, rule-separated panel.
- Menu items use large tap targets and persistent labels.
- Reduced motion opens instantly or with a short opacity change.

Navigation components:

- `Nav/Top`
- `Nav/MobilePanel`
- `Nav/SectionLink`
- `Nav/Wordmark`

## Focus States

Create and document global focus treatment:

- Keyboard focus ring: 2px `color/signal/lime` with 2px offset.
- On media or dark raised surfaces, add a 1px dark inner separation if needed for contrast.
- Focus styles apply to links, buttons, nav items, media controls, menu close, and carousel/reel controls.
- Focus order should follow visual order.
- No component should remove the default outline unless the custom focus state is present.

## Hover States

Hover should clarify intent without becoming the only way to read content.

Patterns:

- Media hover: scale from 1 to approximately 1.03.
- Rule hover: default rule to signal or strong rule.
- Project row hover: media, title, and ownership label respond as one group.
- Link hover: underline shifts to signal.
- Button hover: icon translates 2-4px or rule brightens.
- Ticker hover/focus: pause.

Rules:

- Apply rich hover only on precise pointer devices.
- Touch devices get persistent labels and tap states.
- Hover duration: 180-260ms using `cubic-bezier(0.16, 1, 0.3, 1)`.
- Do not reveal essential role, ownership, or project status only on hover.

## Reduced-Motion Alternatives

Every motion demo and production component must have a complete reduced-motion state.

Required alternatives:

- Opening sequence: show completed hero immediately.
- Signal network: show static generated frame or simplified non-interactive network.
- Split text: content appears already visible, or uses an instant clip state.
- Section reveals: no offscreen hidden state; use instant appearance or short crossfade.
- Project thumbnail expansion: use direct navigation or short opacity transition.
- Ticker: static line of text.
- Media hover zoom: disabled.
- Menu: instant open/close or short opacity transition.

No content may depend on animation completing.

## Motion Timing Demos

Create a `Motion Timing` section on the hidden page with labeled demos and run/reset controls.

| Demo | Duration | Easing | Notes |
| --- | ---: | --- | --- |
| Hover response | 180-260ms | `cubic-bezier(0.16, 1, 0.3, 1)` | Rule brightens, icon shifts. |
| Text reveal | 600-750ms | `cubic-bezier(0.16, 1, 0.3, 1)` | Clip reveal, not simple fade-up. |
| Section reveal | 700-900ms | `cubic-bezier(0.16, 1, 0.3, 1)` | Default content remains accessible. |
| Menu open/close | 450-600ms | `cubic-bezier(0.16, 1, 0.3, 1)` | Focus trap if overlay is used. |
| Project transition | 700-950ms | `cubic-bezier(0.16, 1, 0.3, 1)` | Thumbnail expands toward hero. |
| Metadata delay | 90-140ms after title | same easing | Metadata enters after title. |
| Ticker pause | immediate to 180ms | same easing | Pause on hover and focus. |

Demos should use abstract shapes, placeholder project names, and verified labels only. They should prove timing and hierarchy without creating final case-study claims.

## Framer Risks

- Framer text styles may not support the full `clamp()` behavior from `SPEC.md`; breakpoint-specific styles may be required.
- RGBA color variables can be awkward in some Framer token workflows; separate rule styles may be needed.
- Hidden pages can still become visible if linked, included in navigation, or published without noindex settings.
- Native Framer interactions may not fully respect `prefers-reduced-motion`; later code components or conditional variants may be needed.
- Complex shared project transitions may exceed native Framer interaction limits.
- Fonts must be loaded with only required weights; unavailable font weights can cause layout drift.
- The signal canvas and custom cursor should not be implemented on the design-system page unless performance fallbacks are already planned.
- Component variants can drift if naming is not strict from the start.
- Project access and exact Framer API methods must be verified after connection; do not guess implementation calls.
- Current repository has no existing code tokens, so the Framer page will be the first concrete design-system artifact.
